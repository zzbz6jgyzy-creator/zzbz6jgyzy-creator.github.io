01 — Product

What it is

Chat Grok

Answers a question

Useful for a single turn. The relationship resets every session.

Grok Bot

Keeps the job

A named teammate with memory and a cloud computer. Still working after you close the laptop.

Own conversation

Name, description, avatar, and context that compounds.

Shared computer

Browser, files, terminal — one machine for every Bot on the account.

Parallel work

Several Bots can run at once. One computer-use task per Bot at a time.

Same roster

Desktop and phone stay in sync. It is not a flowchart builder, and it is not Muse.

The computer is per account, not per Bot. Files, logins and browser sessions are shared. A second Bot is not a security boundary.

03 — Setup

Install and sign in

Download from x.ai/bot. Desktop is the full product. Mobile is the same Bots, not a second roster. The app updates itself — Settings → Updates if you want to force it.

macOS

Apple silicon or Intel. Drag to Applications. Chip in About This Mac means silicon; Processor means Intel.

Windows

x64 or Arm64 installer, then Start menu. Check Settings → System → About → System type.

Linux

.deb, .rpm or AppImage. uname -m: x86_64 is x64, aarch64 is Arm64.

Phone

iPhone / iPad on iOS 18+. Android 9+. Same signed-in Bots as the desktop app.

  1. 01Sign in on the welcome screen. Later: Settings → Sign In with Cursor.
  2. 02Finish in the browser window, then return to the app.
  3. 03If access is SuperGrok, link it. Desktop: Settings → Usage & Billing. Phone: Link Grok Account, then refresh status.
  4. 04First launch asks which tools you use. That only shapes teammate suggestions — it does not connect Gmail or Slack.

Grok Bot uses your Cursor account. Work SSO is the normal organisation sign-in.

04 — Hire

Create a Bot

Focused Bots beat one catch-all. Split when the work has a distinct goal, toolset, working style, approval line, or schedule.

  1. 01New in the sidebar, or Cmd/Ctrl+N.
  2. 02Create new Bot — or type a name and choose Create “name” Bot.
  3. 03Bot menu → Edit Profile: name, label, description, avatar.
  4. 04Give it a concrete first task. Do not start with “what can you do?”

Description

Standing rules. “Never send external messages without approval.”

Message

Today’s work. “Draft follow-ups for these twelve accounts.”

A description that works

Own the weekly account-health review. Pull product usage and support signals, flag evidence of churn or expansion, and produce a linked watch list. Never contact a customer or change an account without approval.

Pin what you use. Hide what you do not — hiding does not pause routines. Duplicate a role for a new region. Delete only if you are done: conversation and routines go; shared-computer files and logins can remain.

05 — Brief

A first task that actually finishes

A strong request has five parts. Skip any one and you get a chat, not a handoff.

01 Outcome

What is finished?

02 Sources

Apps, files, threads.

03 Constraints

What it must not do.

04 Deliverable

What it returns.

05 Review

When it stops.

Five minutes, no login

Summarize this document in five bullets. List every date, decision, and open question in a separate section. Cite the page or section for each item. Do not change the source file.

Then a real tool, still read-only

Open our analytics dashboard and compare new-user activation for this week with the previous four weeks. Identify the largest step-level change and draft a short investigation plan with links to the relevant charts. Do not change any dashboards. Ask me to sign in if needed.

Dictate with Cmd/Ctrl+D, or Start dictation on the phone. After the first result, name the preference: “Five bullets, source links inline, final section called Decisions needed.” That is how it gets smarter.

Official use-cases are the same shape: research, draft, stop for review. Add send / change / publish later, behind approval.

06 — Computer

Tools and takeovers

A login, CAPTCHA, passkey or two-factor prompt should hand the computer to you. The Bot does not invent a bypass.

  1. 01Open Agent Computer from the conversation.
  2. 02Take over. Enter the password, passkey, 2FA or CAPTCHA yourself.
  3. 03Give control back. That session lives on the shared computer.

Marketplace plugins are more reliable than driving a site by hand — use a connector when one exists. If a site blocks automation or expires the session, that is normal. You finish the human step.

07 — Repeat

Skills vs routines

Skill

How to do the task. Walk it through once, or record Teach a task (up to ten minutes) and review the draft.

Routine

When to run it — on a schedule, or after an event. Only after the skill works on a second input.

  1. 01Job, sources, format and boundaries in the description.
  2. 02One real task with a safe scope. Correct until it is reviewable.
  3. 03Save as a skill. Test on a second input.
  4. 04Create a routine only when retries and failures are defined. Keep send/change behind approval.

08 — Roster

More than one Bot

One outcome

Each Bot owns an end-to-end job. Do not make yourself the router.

Add specialists

Only when the role is stable — a distinct goal, toolset, or schedule.

Group chat

Use it when the handoff itself needs to be visible.

Ask before spawning

Conversations stay per Bot. The computer does not.

Marketplace and share links create a copy on your account — not their computer, logins or history. A public link shows the config. Strip keys, internal URLs, anything you would not paste in a public doc. Adding a shared Bot accepts the third-party bot terms.

10 — Guardrails

Approvals and the shared computer

Always stop

Passwords, 2FA and CAPTCHAs hand the computer to you.

Ask first

Sending, publishing, deleting, purchasing, or changing production.

Description first

Standing boundaries live there. Auto-review can enforce some of them.

Trust live systems

Memory is a summary, not an authority. Reopen the source for a decision that matters.

Training opt-out follows your Cursor privacy settings. Between users, isolation is strict. On your own account, assume every Bot can see the computer.

Lauren Tan at SpaceXAI said the bots run on Claude Opus 5.5 and can spawn cloud agents on whatever Cursor models they have. Repeat the names if a Bot will sit near money, mail, or a car.

11 — Car

If you want it on a Tesla

Vehicle access is a plugin problem, not a prompt trick. Ask the Bot to walk the current Tesla developer flow — that path changes; a frozen screenshot goes stale.

Grant

State and commands you actually want: climate, battery, lock status. First job is a commute schedule, not a party trick.

Keep behind ask

Unlock, remote start, and anything that moves the car. Sunday check: battery, and whether it needs a plug.

If a bot is allowed near a Tesla, the approval line belongs in the description before the first command, not after the first mistake.

12 — Spend

When it is worth it

Hire when

A weekly digest, a watchlist, a car that is actually warm, or a research beat that still exists next Tuesday.

Skip when

You open it when you are bored. A Bot with no standing job will not earn the weekly usage.
