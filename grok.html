Level 1

Introduction

A Bot is a durable teammate: a name, a job, its own conversation, and context that compounds. You work with it by sending a message — type, dictate, or start a voice chat. It takes on multi-step work in real apps and websites, updates you in the conversation, and stops when something needs approval.

That is the difference people miss. Chat Grok resets the useful part of the relationship every session. A Bot is supposed to still know the job on Thursday.

Five things make it different from a chat window:

  • A computer. Each Bot works on a persistent cloud machine with a browser, a filesystem and a terminal. Work continues with the laptop closed.
  • Setup is a message. There is no flowchart builder. Create a Bot, describe the job, grant access when it asks.
  • Bots can coordinate. They can run in parallel, message each other, share a group chat, and pass ownership of a task.
  • They learn a path once. Walk a Bot through a workflow, save it as a skill, then run that skill on a schedule.
  • Context compounds. Memory, files, browser sessions and preferences stay with the Bot instead of resetting.

All of your Bots share one computer. Files, logins and browser sessions belong to the account, not to one Bot. A second Bot is not a security boundary. Isolation between different users is strict.

Access is included with every paid individual Cursor plan and with Cursor Teams, or by linking an individual SuperGrok, SuperGrok Plus or SuperGrok Heavy subscription. Usage resets weekly. If both Cursor and SuperGrok are linked, Grok Bot uses whichever has more remaining usage.

It is not Muse, and it is not a flowchart product. The same Bots sync on desktop and on the phone. The computers they work on run in Cursor’s cloud.

Level 2

Beginner

Goal of this level: one Bot, one finished task, no connectors. If that works, the rest of the product makes sense. If it does not, adding tools will not fix it.

What you need

  • An eligible plan — paid Cursor, Cursor Teams, or a linked SuperGrok tier. Check the current matrix in the FAQ.
  • The desktop app for macOS, Windows or Linux. Mobile is the same Bots, not a second product.
  • Cloud data storage. Cursor accounts still on Legacy Privacy Mode have to switch before the app will start.

Install

Download from x.ai/bot.

  • macOS — Apple silicon or Intel. Open the disk image, drag Grok Bot to Applications, then Open if macOS asks. Apple menu → About This Mac: a Chip field means Apple silicon; Processor means Intel.
  • Windows — x64 or Arm64 installer, then Start menu. Settings → System → About → System type if you are unsure.
  • Linux — x64 or Arm64 as .deb (Debian/Ubuntu), .rpm (Fedora/RHEL), or AppImage. uname -m: x86_64 is x64, aarch64 is Arm64.
  • Phone — iOS or iPadOS 18 or later; Android 9 or later.

The app checks for updates itself. Settings → Updates if you want to force it.

Sign in

  1. Choose Sign in on the welcome screen. Later: Settings → Sign In with Cursor.
  2. Finish in the browser window that opens.
  3. Come back to the app when the browser confirms it.
  4. If access comes from SuperGrok, link it when asked. Desktop: Settings → Usage & Billing. Phone: Link Grok Account, then Finished Linking? Refresh My Status.

Grok Bot uses the Cursor account. If work uses SSO, complete the normal organisation sign-in. On first launch it introduces Bots, the shared computer and routines, then asks which tools you use. Those answers only shape teammate suggestions. They do not connect Gmail or Slack by themselves.

Create the first Bot

Official rule, and it is the right one: focused Bots beat one catch-all. “General Helper” gives it nothing to remember against.

Give it a short name, one primary job, and a description of how it should work. Example from the docs:

Name: Piper
Job: Product performance
Description: Investigate product-performance questions using our observability tools. Preserve links and screenshots, separate evidence from hypotheses, and return a short summary with the highest-impact issue first. Never change production settings.
  1. New in the sidebar, or Cmd/Ctrl+N.
  2. In New chat, choose Create new Bot — or type a name and choose Create “name” Bot.
  3. It opens as New Bot. Bot menu → Edit Profile: name, label, description, avatar.
  4. Give it a concrete first task. Do not start with “what can you do?”

Put standing rules in the description. Put today’s work in the message.

A first task that actually finishes

A strong request has five parts: outcome, sources, constraints, deliverable, review point. Five minutes, no login — attach a document:

Summarize this document in five bullets. List every date, decision, and open question in a separate section. Cite the page or section for each item. Do not change the source file.

Dictate with Cmd/Ctrl+D on desktop, or Start dictation on the phone. Start voice chat is a live conversation. When the result is wrong, name the lasting preference out loud: 

Use this format for future weekly reports: five bullets, source links inline, and a final section called Decisions needed.

That sentence is how the Bot gets smarter. Not by magic. By naming the preference, then promoting anything that should stay true into the description.

Level 3

Intermediate

Goal of this level: the Bot works in a real tool, you can take over for a login, and a good run becomes a skill you can call again.

Give it a real tool, still read-only

Open our analytics dashboard and compare new-user activation for this week with the previous four weeks. Identify the largest step-level change and draft a short investigation plan with links to the relevant charts. Do not change any dashboards. Ask me to sign in if needed.

Roles that work well in the official use-cases are all the same shape: research, draft, stop for review. Sales outbound. Talent scout. Paid media. Expenses. Product performance. Bug reproduction. Account health. Start with read-and-prepare. Add send, change or publish later, behind approval.

When it hits a login

Passwords, passkeys, two-factor codes, CAPTCHAs and payment checks should hand the computer to you. Do not paste secrets into ordinary chat.

  1. Open Agent Computer from the conversation.
  2. Take over.
  3. Enter the password, passkey, 2FA or CAPTCHA yourself.
  4. Give control back and tell it to continue.

That browser session lives on the shared computer, so other Bots can reuse it when that is appropriate. For supported services, Marketplace in the sidebar has plugins you authenticate in the browser. Use a connector when one exists — it is more reliable than driving the site. In chat, type @ to attach a connector, Bot, group or routine. Type / to reference a saved skill.

A site can still block automation, expire a session, or demand a human. That is normal. The Bot stops. You finish the human step.

Description versus message

  • Description: “Never send external messages without approval.”
  • Message: “Draft follow-ups for these twelve accounts.”

A description that works sounds like operations, not branding:

Own the weekly account-health review. Pull product usage and support signals, flag evidence of churn or expansion, and produce a linked watch list. Never contact a customer or change an account without approval.

Create a separate Bot when the work has a distinct goal, a distinct set of tools, a distinct working style, a distinct approval line, or a recurring schedule. Pin active Bots. Hide ones you are not using — hiding does not pause routines. Duplicate a role for a new region or product. Delete only when the conversation and routines should go. Shared-computer files and logins can remain after a delete.

Save a skill

A skill is how to do a task. Skills are one library shared across your Bots; a Bot still needs the relevant connector or login to use one. A useful skill states when to use it, the required inputs, the sequence, how to validate, what to return, and what requires approval. 

Save the process we just used as a skill called “Weekly account health.” Include the source systems, risk definitions, output format, and the rule that customer contact always requires approval.

If a private skill does not appear in the / menu, open Marketplace → Your plugins → Manage plugins and skills and check it is listed under Private skills.

Search and read X

Bots can search and read what is public on X without connecting an X account. Ask one to search posts, open a post from its link, read an account’s posts and mentions, see who quoted or reposted something, count recent posts on a topic, or check trends and news. That access is read-only and does not sign in as you.

DMs, bookmarks, the home timeline, or who liked your posts need the X plugin from Marketplace, signed in with X.

Level 4

Advanced

Goal of this level: unattended work that is still under control. Skills first. Routines second. Approvals before anything that sends, spends, deletes or changes production.

Teach a task

When Teach a task is available, demonstrate a browser workflow instead of describing every click.

  1. Open a one-to-one Bot conversation and its computer view.
  2. Choose Teach a task.
  3. Describe the result you are about to demonstrate.
  4. Perform the workflow once — up to ten minutes. It does not record microphone audio.
  5. Stop, review the draft skill, and add the decision rules a single example will miss.
  6. Test on a safe input before you schedule it.

Avoid exposing secrets during the demonstration. Use the secure handoff flow for credentials. If the control is not visible yet, ask the Bot to create a skill from the written instructions and the completed task.

Create a routine

A routine tells one Bot when to run a workflow — on a schedule, or after a supported event. Background routines run while the laptop is closed. Ask the Bot that should own the job: 

Every weekday at 8:00 AM, run the Daily customer-risk skill against the current account list. Post a linked watch list in this conversation. Do not contact customers. If the source data is unavailable, report the failure instead of using old data.

Confirm the owning Bot, the schedule and time zone, the input source, the expected result, the approval boundary, and what happens when a source is missing.

Cursor account integrations can start a routine from an event — a Slack message or a GitHub notification. Those are separate from Slack or GitHub plugins and may need their own connection. Keep the match narrow. “Every new message” burns usage and acts on noise. 

When a message in #customer-escalations contains a support ticket link and the phrase “needs repro,” open the ticket, reproduce the issue in staging, and post a repro pack in this conversation. Never post back to Slack without approval.

A test run does real work. It can navigate websites, change files and call connected tools. Use safe inputs. Keep write actions behind approval.

After a test, check that it picked current inputs, that the output matches the format, that every action has a source, that it stopped at the approval point, and that failure is explicit. A Bot can own up to 50 routines. The app keeps the 20 most recent runs each. Schedules must be at least five minutes apart. Deleting a routine is immediate and has no undo. After a long time away, Grok Bot may ask whether to keep routines running and pause them if nobody answers.

Desktop: click the Bot name → Tasks (or View conversation details → Routines). Phone: the Bot profile lists routines and run history.

Approvals and Auto Review

Keep these behind an explicit stop:

  • Sending messages or invitations
  • Publishing
  • Purchases and transfers
  • Deleting or overwriting data
  • Changing permissions
  • Production changes
  • Accepting legal terms

The conversation shows the proposed operation and its inputs. Allow once continues that action. Always allow can save a matching rule. Deny blocks it. An approval does not undo work already done. An approval from a routine, a trigger or another Bot expires after about ten minutes; the action does not run. Ask the Bot to try again.

Settings → General → Auto-review. Ask first always stops a matching action. Allow automatically lets a match through only if nothing else wants to stop it. If both match, Ask first wins. Write narrow rules:

  • Ask first before sending any external email.
  • Ask first before changing a production dashboard.
  • Allow automatically when running git status in /workspace/reports.

Do not write “allow everything in the browser.” Personal Auto-review rules live on the current desktop and sync to that Grok Bot computer. Another install needs its own. A team admin can lock stricter rules you cannot edit.

The local computer is a separate switch

The shared Grok Bot computer is in the cloud. Running commands on the Mac or Windows machine in front of you is optional. Settings → General → Bot → Execution on Local Computer: Ask every time, Always allow, or Never allow. Default is Ask every time. Use Never allow unless there is a specific reason. A team admin can cap this; the stricter policy wins. These settings do not stop the cloud computer.

Hardware security keys (YubiKey and similar) can be used in the Bot’s browser when Use hardware security keys is on under Settings → General → Security Key. Default on is macOS and Windows; not yet on Linux. Every use asks first.

Memory is not a source of truth

A Bot keeps stable preferences, role context and summaries. It does not replace the live system. For a decision that matters, tell it to reopen the current source. Correct stale assumptions in the conversation. Promote anything that should stay true into the description.

More than one Bot

Start with the smallest useful set. One Bot owns an end-to-end outcome. Add another only when there is a stable specialist role. Put them in a group chat when the handoff itself needs to be visible — a coordinator, an editor and a reviewer in one thread, instead of you being the router. Conversations and learned memory stay per Bot. The computer does not.

Existing Bots can suggest a new specialist. Ask before you let it spawn a crowd. Marketplace Bots and shared templates create a copy on your account. The other person does not get your computer, logins or history. A public share link shows the Bot’s configuration — strip API keys, internal URLs and anything you would not paste in a public doc. Shared Bots are other people’s configs; adding one accepts the third-party bot terms.

Tag @bot on X

Tag @bot in a post or a reply. The main Bot picks the post up as a task; @bot confirms with a short public reply. The work stays in the Grok Bot app. @bot only posts the confirmation. That needs an X account connected to the Grok account.

Tagging is not available for X accounts based in Australia, the United Kingdom, the European Union, Iceland, Liechtenstein or Norway. The first tagged request also sends an X notification that the work starts automatically and uses Grok Bot usage.

  • A short “sent to your Grok Bot” reply — open the app and review.
  • “Sign up for Grok Bot” — no Grok account is connected to that X account.
  • “Grok Bot isn’t set up yet” — accounts are connected, but there is no Bot yet.

It also stays silent if the region is blocked, if you did not tag @bot yourself in a thread that already has it, if the post also tags @grok, if a video or GIF is in the post or the quoted post, if moderation stops it, or if weekly usage is gone.

When you should stop

Design unattended work so a miss is boring:

  • Automate preparation before execution. Draft, reconcile, recommend — then ask.
  • Include a no-data and stale-data policy. Never silently reuse last week’s file.
  • Make retries idempotent where you can.
  • Tell it where to report partial completion.
  • Re-test after a website, connector or source format changes.
  • Pause a routine when the source system changes.
  • Sign out of a site, revoke a connector, and delete temporary files in /workspace when a project should no longer be available. Deleting a Bot does not wipe the shared computer.

Repeat the model names if a Bot will sit near money, mail, or a vehicle. Vehicle access, where it exists, is a plugin problem — grant only the commands you actually want, and put the approval line in the description before the first command.
